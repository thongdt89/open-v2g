# Portable limit, readiness and session lifecycle implementation

Revision: Draft 0.1 — 30/10/2026. Host implementation after baseline `346c11f`.
This extends the two-composition design under Atomic Rev.3 §§4–5, 8–10, 25–26.
All new types and operations are PROJECT interfaces, not supplier-generated RTE
or imported AUTOSAR ABI. No formal freeze or conformance is asserted.

## Independent limits and permission

Vehicle energy snapshots remain immutable. Cable, peer and selected schedule
bounds have separate `OpenV2g_LimitEvidence` records: source, generation,
sequence, timestamp/quality, charge mode, correlation, validity and power limits.
PermissionManager intersects every present source with the vehicle envelope.
Zero power/current is restrictive; it is not an unlimited sentinel. Negative
magnitudes, zero maximum voltage, mismatched mode/generation, stale, missing
required, invalid or expired evidence deny permission. Explicit large upper
bounds in the host schedule/cable fixtures represent unconstrained dimensions.

`required_limit_sources` configures the required source mask. The real wire
profile requires all three sources and `require_protocol_readiness`; the legacy
semantic fixtures explicitly default both off. `limit_max_age_us` is required
when the source mask is enabled. Required vehicle INTERLOCK/LIMITS availability,
physical assessment, link, schema/mode and hardware gates remain in force.
Protocol service selection and Authorization Finished are now authoritative HLC
status fields, set only after a correlated successful protocol response. Ongoing
authorization cannot set authorized; stop/error clears the flags.

An allowed permission expires no later than any required source age/validity,
as well as its own configured TTL. Start-assessment validity caps ENERGIZE before
start; after enable, historical start proof and fresh current hardware evidence
have separate roles. Missing or invalid evidence cannot be hidden by renewal.

ProtocolDataFlow projects outgoing targets into the current permission envelope.
The original vehicle snapshot and its limits remain unchanged in the request;
separate `target_voltage_mv`/`target_current_ma` fields carry projected values.
A target inconsistent with its own vehicle snapshot is rejected. Peer reductions
therefore do not masquerade as vehicle capability or mask later vehicle derating.

## Portable session owner and mapper seam

`ISO15118Chrg` owns a bounded `SessionContext`. It retains session/EVSE identity,
selected service/schedule, schedule validity, expected message/correlation,
response validation and monotonic owner timestamps. The Linux mapper projects a
decoded schema-specific response into `OpenV2g_SessionResponse`. The HLC facade
validates it before the mapper publishes peer evidence or advances the adapter.

| PROJECT owner operation | Direction and producer/consumer | Trigger / failure semantics |
|---|---|---|
| `OnLimitEvidence(evidence, now)` | IN, source provider → coordinator; owned copy | Serialized update, no borrowed buffer; unrelated/obsolete discarded, current invalidation revokes; current ALLOW reevaluated on change |
| `SessionContext.Begin(generation, protocol, schema, mode)` | IN, HLC supervisor → session owner | Explicit DIN/ISO-2 schema/mode; clears old context |
| `SessionContext.Expect(request)` | IN, active adapter request → session owner | One outstanding request, nonzero correlation, matching generation/schema/mode and valid kind |
| `ValidateWireResponse(response, now)` | IN, decoded neutral projection → HLC owner | Bounded owned identity data; no publication on validation failure |
| `SessionContext.Consume(kind, correlation)` | IN, validated response → protocol progression | Exact one-use proof; stale, duplicate or mismatched completion rejected |
| `ConfigureCommunication(setup, response)` | IN, host integration → HLC owner | Idle-only configuration; zero retains legacy fixture behavior |
| `TickCommunication(generation, now)` | IN, owner scheduler → HLC supervisor | Enforces aggregate setup, individual responses and cumulative processing budgets |
| `ConfigurePause(enabled, retention)` | IN, host application → HLC owner | Idle-only ISO-2 EIM policy; requires wire validation; DIN/PnC excluded |
| `RequestResume(now)` | IN, application → HLC owner | Requests use of a valid retained context; grants no vehicle permission |
| `BeginRenegotiation(now)` | IN, application → coordinator | Revoke, request measured safe state, clear old peer/schedule/assessment evidence; keep HLC/PLC |

Callbacks still require bounded copy/notification into serialized owners. No
concurrent ISR/RTE task allocation is generated by these function interfaces.
Concrete generated-code DTO mapping and codec instances remain in the optional
host adapter/runner; they are not yet a complete production transport-neutral
codec binding. The portable session owner and ProtocolDataFlow are exercised
both by deterministic tests and actual sockets.

## Bounded timing

The coordinator owns PLC/link setup and stopping/renegotiation deadlines. HLC
owns aggregate SDP/TCP/TLS/SAP setup, per-response and cumulative processing
budgets. Late responses fail during the response operation itself even without
a prior scheduler tick. Old-generation and early timer events cannot expire a
new stage. A new response request arms a new response deadline; Ongoing retries
do not reset the cumulative Authorization/CPD/CableCheck budget.

Host defaults: link/setup/stop/renegotiation budgets are 2 seconds, response
budget 500 ms, retention 5 seconds in lifecycle tests, and limit age 2 seconds
in the wire fixture. These are configurable development values, not normative
protocol timers or vehicle safety deadlines. An independent target watchdog and
reaction if an owner task stops executing remain external integration work.

## Pause/resume

The fixture sends ISO-2 SessionStop Pause after coordinated stopping. Only an
acknowledged, wire-validated stopped context may be retained. Its lifetime is
bounded by configured retention and the previous selected schedule validity.
The volatile retained record includes peer/session/service/schedule and exact
endpoint/transport/security/interface binding. It contains no permission,
authorization result, vehicle evidence or private key.

The host resume API requires measured connected-safe completion, creates a new
generation, invalidates all usable vehicle/limit/assessment evidence and rebinds
the safe simulated hardware generation. Rebinding performs no actuation and does
not restamp an old measurement: its quality becomes INIT until new feedback.
The next run repeats real IPv6 SDP/TCP, TLS when configured, SAP, service
selection, authorization, parameters and physical assessment. OldSessionJoined
must match the retained peer/session and selected bindings. Retention is consumed
once; failed restore, expiry, cancellation/error or mismatch cannot revive it.
No implicit fresh-session fallback or credential/authorization reuse is claimed.

`OvWireClient_PrepareResume` is currently restricted to the discovered IPv6
runner so the binding uses a real discovered endpoint rather than the legacy
injected endpoint. Both AC and DC plain/TLS cases are tested. Nonvolatile
retention, PnC resumption, supplier/OEM recovery policy and exact-edition
interoperability remain qualification/integration work.

## In-session renegotiation

ISO-2 PowerDelivery Renegotiate is encoded/decoded explicitly, sharing the
PowerDelivery response wire type with START/STOP. The coordinator revokes the
old permission before requesting safety, retains communication, and clears peer,
schedule and assessment evidence. Measured safety is required before preparation
can progress. New CPD/schedule and DC or AC readiness produce a fresh permission
before the next enable. This keeps one vehicle state owner and no HLC actuator
path. The host station deliberately changes the selected schedule tuple.

A stop/cancel during renegotiation adopts the in-flight safe-state transaction;
it does not blindly repeat a physical command. Missing confirmation or a stalled
renegotiation expires under coordinator supervision. Actual physical retry,
fallback and electrical sequencing still require the vehicle safety contract.

## Evidence scope

New deterministic regressions cover independent derating/expiry, absent/invalid
sources, authorization Ongoing, schema/session/peer/schedule mismatch, duplicate
response, late setup/response callbacks, retained expiry/security mismatch,
single-use restore, new-generation hardware qualification, renegotiation timeout
and stop races. Socket lifecycle tests run four pause/resume pairs and four
renegotiation sessions across AC/DC and plaintext/TLS.

Six new candidate-constructed lifecycle EXI vectors independently decode and
re-encode byte-identically using the separate pinned oracle. The original 19
feature vectors and 50 earlier references remain unchanged. These are execution
and differential checks, not independent standards-authored goldens, physical
EVSE interoperability, target measurements or safety approval.
